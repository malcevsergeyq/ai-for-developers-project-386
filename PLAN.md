# План и статус проекта

«Запись на звонок» — упрощённый сервис бронирования по мотивам Cal.com (вариант проекта «Календарь звонков», модуль 1). Гость выбирает тип события и свободный слот и записывается без регистрации; владелец календаря создаёт типы событий и смотрит список предстоящих встреч. Раздельные фронт и бэк по требованию задания, взаимодействие — только через API-контракт.

## Стек

- Бэк: Node + Express — `server/`
- Контракт: TypeSpec — `spec/`
- Фронт: React 19 + TypeScript + Vite — `ui/`; shadcn/ui (стиль `base-nova`: Base UI + Tailwind v4), `react-router-dom`. Vue отклонён осознанно: shadcn/ui и Mantine существуют только под React, а Vue-порт лишает смысла shadcn MCP из урока
- Хранилище: PostgreSQL при заданном `DATABASE_URL`, иначе память — две реализации за одним интерфейсом репозиториев

## Ключевые решения (Design First, 2026-08-19)

Урок задаёт жёстко: типы событий с `durationMinutes`, слоты по 30 минут на 14 дней от текущей даты, занятость **глобальная по времени** — две записи на пересекающееся время запрещены даже для разных типов событий.

Урок молчит, решено нами:

- **Сетка стартов 30 минут, бронь занимает `durationMinutes`.** Событие на 60 минут занимает два соседних старта и блокирует их для всех типов. Альтернатива «все события ровно 30 минут» отвергнута: она обесценивает поле `durationMinutes` и убирает единственный интересный случай — пересечение интервалов разной длины. Переиспользуется `server/services/intervals.js`
- **Рабочее окно 09:00–18:00 UTC, только будни.** 18 слотов в день; календарь на фронте выглядит правдоподобно, данных на порядок меньше, чем при круглосуточной сетке
- **Всё время — UTC, ISO 8601.** Таймзон ТЗ не требует, поэтому их нет вовсе — прежнее решение про IANA-таймзону в расписании снято вместе с расписаниями
- **`id` — непрозрачные строки (UUID).** Так в примере урока; заодно исчезает баг из аудита 15.08, где `id` больше `int4` доходил до Postgres и превращался в `500` вместо `404`
- **Слоты не хранятся, а вычисляются** из окна, сетки и существующих броней. Хранить нечего: окно скользит вместе с текущей датой
- **Слот вне окна или мимо сетки → `400`, занятый слот → `409`.** Разные классы: первое — неверный вход, второе — конфликт состояния. Проверка Hexlet требует именно понятного сообщения о конфликте
- **Формат ошибки `{error, message}`** сохранён от прежнего контракта — конвенция проекта не изменилась
- **У владельца только создание типов событий и просмотр встреч.** Ни `PATCH`, ни `DELETE`: ТЗ говорит «создаёт типы событий», остальное — сверх задания
- **`eventTypeTitle` дублируется в `Booking`**, чтобы список владельца рисовался одним запросом без джойна на фронте

## Долг от прежнего скоупа — закрыт 2026-08-19

Расписания доступности, их сервис, роуты, маппер и тесты удалены. `schema.sql` переписан
под новый контракт. `intervals.js` заменён на `time.js`: функция пересечения интервалов
переехала как есть, арифметика `HH:MM` внутри суток уступила место работе с моментами UTC.

Четыре бага из аудита 15.08 закрыты: переполнение `id` невозможно (идентификаторы —
строки), catch-all отдаёт `{error, message}`, `entity.too.large` и `encoding.unsupported`
получили свои коды вместо 500, `cors()` принимает список origin из `CORS_ORIGIN`.

## Открытые вопросы

- **Postgres так и не поднят — подъём отложен осознанно (решение 2026-08-19).** Идём в шаг 5 с непроверенной pg-веткой. Что это значит на практике: приложение проходит проверку и работает на in-memory, но если на деплое задать `DATABASE_URL`, оно уйдёт в код, который не исполнялся ни разу — и упадёт уже в проде, а не в тестах. Поэтому деплой с `DATABASE_URL` включать нельзя, пока база не поднята и схема не накатана. Не проверены: exclusion-ограничение `bookings_no_overlap`, `gen_random_uuid()`, приведение `id::text` и перевод SQLSTATE `23P01` в 409.
- **`/admin/*` ничем не защищён** — авторизация вынесена ТЗ за скоуп, так и остаётся
- **Демо-данные засеваются при пустом хранилище** (два типа встреч в `server/index.js`). Решено 2026-08-19: иначе проверяющий открывает пустую страницу и до пути записи не доходит. Если это нежелательно в проде — убрать за флаг окружения
